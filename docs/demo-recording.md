# 30 秒演示视频录制（OBS）

目标：一条 30 秒、1080p30 的无声演示，完整走通
**选中设备 → 打开 → 检测框 → OK / NG 计数 → 状态栏性能数据**，
让招聘方在不运行代码的情况下也能看懂项目做了什么、性能如何。

## 1. 录制前准备

- 用 Release 产物运行，确认左侧设备列表能正常枚举；先完整试跑一遍，避免录制时才发现设备被占用；
- 摄像头固定（三脚架 / 支架），背景用深色哑光纸或黑布，保持均匀、无明显反光；
- 准备两个工件：
  - **OK 件**：浅色长方形（长宽比 1~4，横放竖放或倾斜摆放均可），完整入镜、面积占画面 1%~60%、短边不小于画面短边 2.5%；
  - **NG 件**：圆片 / 圆角很大的片（矩形度 0.75~0.85）、长宽比 4~6 的长条，或面积明显超过 60% 的大件，用于触发红色 `NG` 框；
  - 注意工件要**比背景亮**（浅色工件放在深色哑光背景上）；如果拍摄深色工件（如浅色桌面上的手机），
    需在左侧勾选 **深色工件（浅色背景）** 切换反向阈值，演示时保持同一极性不要中途切换；
- 关闭聊天软件与系统通知（Windows 专注助手），避免弹窗入镜；
- 显示缩放建议 100%，保证状态栏数字在 1080p 视频里可读；
- 程序启动后保持「未打开设备」状态，检测开关保持默认勾选。

> 计数需要目标连续出现 5 帧（约 0.17 s）才确认；界面计数每秒刷新一次。
> 每个工件在画面里至少停 **1.5 s**，看到 HUD / 左侧计数变化后再拿走。

## 2. OBS 设置

| 项目 | 建议值 |
| --- | --- |
| 画布 / 输出分辨率 | 1920 × 1080 |
| 帧率 | 30 FPS |
| 来源 | **窗口采集** `cppShowCameraTest.exe`（Windows 10 1903+ 用 “Windows 10” 采集方式），只截客户区，不带桌面 / 任务栏 |
| 编码器 | 硬件编码（NVENC / QuickSync）或 x264，CQP 18~20，关键帧 2 s |
| 录制格式 | `mkv`，录完在 OBS「文件 → 重新封装录像」转 `mp4` |
| 音频 | 关闭麦克风与桌面音频（纯字幕演示；需要旁白再开麦） |
| 光标 | 录制鼠标指针（选择设备时需要看到点击） |
| 布局 | 程序窗口等比放大到画布内，右侧留字幕条；不要拉伸变形 |

可选增强：

- 添加两个 **文本源（GDI+）**：左上角标题 `cppShowCameraTest v3.0.0-algo`，底部步骤字幕；
- 再做一个“状态栏特写”场景：同一窗口采集源放大裁切到状态栏，17~23 s 切换过去，
  让「采集 FPS / 处理 FPS / 耗时 ms / 队列深度」在视频里清晰可读；
- 字幕用 36~40 px 白字 + 半透明黑底，避免压在检测框上。

## 3. 30 秒分镜

| 时间 | 画面 / 操作 | 字幕 |
| --- | --- | --- |
| 0 ~ 2 s | 程序主窗口（未打开设备），标题与设备列表 | `C++17 / Qt / OpenCV · 采集卡枚举 → 预览 → 检测计数` |
| 2 ~ 6 s | 鼠标选中设备 → 点击「打开设备」→ 实时画面出现 | `① 选中设备并打开` |
| 6 ~ 12 s | 放入 OK 件，出现绿色框与 `OK`，HUD 计数 +1 | `② 检测框 + OK 判定` |
| 12 ~ 17 s | 拿走 OK 件，放入圆片或长宽比 4~6 的 NG 件，出现红色框与 `NG` | `③ 超规格 → NG` |
| 17 ~ 23 s | 连续放入 2 个 OK 件，累计计数增长；切状态栏特写 | `④ 累计 OK / NG 不重复计数` |
| 23 ~ 27 s | 状态栏特写：分辨率、采集 / 处理 FPS、耗时 ms、队列深度 | `⑤ 性能数据（见 README）` |
| 27 ~ 30 s | 切回主画面 + 结束卡：仓库地址、tag、README 入口 | `v3.0.0-algo · github.com/X-Y-Z-R/cppShowCameraTest` |

录制时按这个节奏走一遍即可，成片控制在 **28~32 s**，不要为了凑时长加无关镜头。

## 4. 录制与检查

1. OBS 先点「开始录制」，数 3 秒再操作，避免片头截断；
2. 每个工件停留 1.5 s 以上，确认左侧「检测：当前 / OK / NG」与画面 HUD 都变化；
3. 结束前保持画面 2 s，便于剪辑加结束卡；
4. 录完检查：
   - 时长 30 s 左右、1920×1080、30 fps；
   - 状态栏数字不糊、检测框颜色可辨；
   - 没有桌面图标、通知、个人信息入镜；
   - 视频里能看清“选中 → 打开 → OK → NG → 计数 → 性能”的完整链路。

## 5. 填写 README 性能数据

录制当天按 README「性能数据 → 如何复现与填写」记录三组数据：

- 检测开启：采集 FPS / 处理 FPS / 平均耗时 / 峰值耗时 / 两个队列深度；
- 检测关闭：同样一组，作为纯转发基线；
- 勾选「模拟处理耗时 100 ms」：确认队列深度上升但画面仍流畅。

把 `待实测` 替换为实测值后再提交，避免把设计目标写成实测结果。

## 6. 上传与发布

```bat
:: 提交代码与文档
git add -A
git commit -m "feat: 阶段3 示例检测 + OK/NG 计数 + 处理耗时"
git tag -a v3.0.0-algo -m "阶段3：示例检测 + OK/NG 计数 + 处理耗时监控"

git push origin --tags
```

1. GitHub → **Releases → Draft a new release**，选择 `v3.0.0-algo`；
2. 上传转码后的 `demo-30s.mp4` 作为附件（建议 < 50 MB），标题写清阶段内容；
3. 把 Release 视频链接替换到 README「演示视频（30 秒）」的待录制位置；
4. 视频文件不提交仓库（`.gitignore` 已排除 `*.mp4`），只提交链接 / 必要截图。

> 如果希望 README 直接内嵌预览，可另导一个 ≤ 10 MB 的 GIF 放到 `docs/assets/`；
> GitHub 不支持在 README 里直接播放 mp4，链接到 Release 是最稳的做法。
